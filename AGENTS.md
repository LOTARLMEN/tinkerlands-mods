# Tinkerlands Mods Installer

Самостоятельный публичный проект установщика. Общение и интерфейс по-русски.
Референс поведения: LOTARLMEN/risen-mods, installer/, MIT; чужие игровые файлы
или графику не включать. Склад в родительском проекте поставлен на паузу.

Приложение: Windows Forms, C# 5 / .NET Framework 4.8, standalone EXE без NuGet.
Сборка build.ps1; значимые проверки build/TinkerlandsModsInstaller.exe --self-test.
Не использовать GUI-автоматизацию и не запускать/закрывать игру при тестах.
Файловые испытания выполнять в fixtures временных папок, не в установленной игре.

DLL модов: mods/native/<mod-id>/*.dll. Адаптеры: mods/*.mod.
Состояние/транзакции/резервные копии: .tinkerlands-mods/, вне mods.
Не записывать EXE/data.win/штатные DLL/настройки/сохранения игры.
Не менять чужие или изменённые файлы; проверять хеши, пути, reparse points,
дубликаты, владение, прерванные транзакции. Удаление только по учёту своих файлов.
Разработка модов остаётся DLL; установщик является отдельным инструментом.

В публичный репозиторий не добавлять игровые файлы/сохранения/логи/учётные данные,
родительский modding/ и исследовательские дампы. Новые моды публиковать через
каталог с точными хешами и воспроизводимую упаковку; не выдавать прототип за готовый мод.

## Принятая структура GitHub и пакетов — 2026-11-17

Публичный репозиторий: https://github.com/LOTARLMEN/tinkerlands-mods.
Локально это самостоятельный git-проект modding/mod-installer/ в рабочем каталоге
Tinkerlands. Родительский проект игры не добавлять в этот репозиторий.

В git хранятся исходники и правила упаковки:

```text
src/                         # приложение установщика
tests/                       # проверки установщика
tools/package.py             # сборка каталога и архивов
catalog/mods.json            # исходное описание всех предлагаемых модов
mods/<mod-id>/
  info.json                  # метаданные адаптера, с сохранением авторства
  script.json                # id, key, event; код берётся из source
  src/                       # GML-адаптер и исходники собственной AMD64 DLL
  build/                     # локальные результаты сборки, не коммитить
build/, dist/                # результаты установщика и упаковки, не коммитить
```

Имена внутри src/ произвольны: поле `source` записи catalog/mods.json указывает
GML-файл относительно mods/<mod-id>/, по умолчанию src/main.gml. Нативные исходники
и их сборочный скрипт хранить рядом в папке этого же мода. Новую игровую логику
писать в DLL; GML оставлять адаптером загрузки, событий, данных и штатного GUI.
Не переносить в git собранные DLL, .mod и ZIP вместо их исходников.

Каждой записи каталога нужны стабильный `id` (строчные латинские буквы/цифры,
разделитель «-»), title, числовая version вида X.Y.Z, description, adapter,
source, dependencies и game_sha256. `adapter` — постоянное имя файла, например
mod_menu.mod; его не менять при обновлении. Для DLL используется массив `native`:

```json
"native": [{"source": "build/example.dll", "name": "example.dll"}]
```

Сборщик помещает эту DLL в mods/native/<mod-id>/example.dll. Этот же относительный
путь должен быть явно указан в загрузочном адаптере. Старые моды с DLL в корне
или абсолютными путями нельзя просто добавить в каталог: сначала адаптировать
пути, проверить совместимость и откат. Для адресно-зависимых DLL фиксировать
допустимые SHA-256 EXE. Существующие script/item/interactable ID сохранять.

Готовые бинарные файлы размещаются в GitHub Releases, а не среди исходников:

```text
Releases / vX.Y.Z /
  TinkerlandsModsInstaller.exe
  catalog.json
  SHA256SUMS.txt
  Tinkerlands-<mod-id>-<mod-version>.zip   # отдельный архив для каждого мода
```

ZIP содержит только перечисленные в каталоге файлы относительно папки игры:
mods/<adapter>.mod и, если нужны, mods/native/<mod-id>/<name>.dll.
Корневая DLL/proxy, игровые файлы, сохранения и резервные копии в пакеты не входят.
Состояние установщика и резервные копии создаются уже у пользователя в
.tinkerlands-mods/ вне mods; пользовательские настройки при удалении сохраняются.

Установщик читает catalog.json из последнего опубликованного обычного релиза,
не из catalog/mods.json в main и не из draft/prerelease. Каждый релиз публиковать
полным комплектом: EXE, каталог, суммы и ZIP всех модов этого каталога. В итоговом
каталоге должны быть HTTPS URL, SHA-256 архивов и пути/SHA-256 каждого файла.
Старые релизы сохранять, опубликованные версии не заменять незаметно.

Для публикации поднять Program.Version и AssemblyInfo, версии изменённых модов
в info.json/каталоге, выполнить build.ps1, tools/package.py и применимые проверки.
Тег релиза vX.Y.Z сейчас обязан совпадать с версией установщика — так устроен
сборщик. После публикации сверить GitHub asset digests и анонимное скачивание.
Актуальная версия установщика — 0.1.1; сейчас предлагается только mod-menu0.1.6.
Склад остаётся на паузе и не включён в каталог как готовый мод.
