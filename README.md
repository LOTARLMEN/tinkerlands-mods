# Tinkerlands Mods

Один установщик для поиска Tinkerlands, скачивания, обновления и удаления модов.
Интерфейс на русском. Установщик также обновляется из GitHub Releases.

## Скачать и запустить

[Скачать TinkerlandsModsInstaller.exe](https://github.com/LOTARLMEN/tinkerlands-mods/releases/latest/download/TinkerlandsModsInstaller.exe)

1. Запустить EXE из любой папки. Установка самого приложения не требуется.
2. Папка Tinkerlands находится через Steam и его библиотеки на разных дисках.
   При необходимости указать её кнопкой «Обзор».
3. Нажать на мод, чтобы открыть справа его описание, автора и версии. Установленные моды отмечены в списке.
4. Закрыть игру, отметить нужные моды галочками и нажать «Установить / обновить». Прогресс и результат видны в строке каждого мода.
5. У мода с новой версией есть отдельная кнопка «Обновить». Для удаления отметить установленные моды и нажать «Удалить выбранные».

Нужна 64-битная Windows с .NET Framework 4.8. Python, Node, Steam API-ключ
и вход в GitHub не нужны. EXE не подписан сертификатом.

В каталоге доступны **Меню модов 0.1.6** и **Мультихранилище 0.0.42**.
Подключившийся игрок может переносить стаки через Shift+ЛКМ между инвентарём
и открытым сундуком. Соседние сундуки доступны для просмотра.
[Описание мультихранилища](mods/chest-network/README.md)

## Где находятся файлы

```text
Tinkerlands/
  tinkerlands.exe                    # файл игры, не изменяется
  data.win                          # файл игры, не изменяется
  mods/
    mod_menu.mod                    # адаптер мода
    native/<mod-id>/<name>.dll       # отдельная папка каждой нативной части
  .tinkerlands-mods/
    installed.json                  # версии и хеши установленных файлов
    transactions/<id>/              # журнал и резервные копии для отката
```

DLL не складываются рядом с EXE. Адаптер нативного мода должен загружать свою
DLL по относительному пути `mods/native/<mod-id>/<name>.dll`.

Перед применением проверяются SHA-256 ZIP и каждого файла, состав архива,
принадлежность путей, зависимости и конфликты ID скриптов `.mod`.
Чужой или вручную изменённый файл не перезаписывается и не удаляется.
Мод из каталога со статусом «Установлен вручную» можно отметить и сразу
удалить кнопкой «Удалить выбранные». Установщик сверяет все файлы мода по SHA-256.
Также определяется локальная сборка «Мультихранилища 0.0.37» с DLL рядом с EXE.

При ошибке записи восстанавливается прежняя версия. После прерванной установки
откат выполняется перед следующей операцией; игру для этого нужно закрыть.
Резервные `.mod` находятся вне `mods`, чтобы игра не загрузила их повторно.
Неизвестные файлы и настройки внутри папок модов сохраняются при удалении.
Удаление уже учтённых модов работает без сети. Для ручной установки подойдёт
текущий каталог GitHub, его сохранённая копия или локальный каталог через `--catalog`.

EXE, data.win, штатные DLL, игровые настройки и сохранения установщик не меняет.
Он не запускает и не закрывает игру, не имитирует клики или ввод.
Диагностика: `%LOCALAPPDATA%/TinkerlandsMods/installer.log`.

## Самообновление

При появлении новой версии в релизе возникает кнопка «Обновить установщик».
EXE скачивается и проверяется по SHA-256 и встроенной версии. Предыдущий EXE
временно остаётся как `.previous.exe`; если запуск новой версии не удался,
он восстанавливается. После успешного открытия новой версии копия удаляется
только при совпадении записанных хешей. Если папка EXE недоступна для записи,
скачать новый установщик по ссылке выше в доступную папку.

## Сборка и проверки

Системный компилятор C# из .NET Framework, без NuGet и сторонних библиотек:

```powershell
rustup target add x86_64-pc-windows-gnu
python mods/chest-network/native/build.py
./build.ps1
python tools/package.py
python tests/e2e.py
```

Встроенные проверки: `build/TinkerlandsModsInstaller.exe --self-test`.
Они работают во временных папках и не затрагивают установленную игру.
Проверяются переносимые пути с кириллицей, установка/обновление/удаление DLL,
конфликты, хеши, откат записи, прерванная транзакция, работа без сети,
сохранение посторонних файлов и запуск заменённого EXE при самообновлении.

CLI для диагностики и автоматизированных проверок:

```powershell
TinkerlandsModsInstaller.exe --list
TinkerlandsModsInstaller.exe --game "D:\Games\Tinkerlands" --install mod-menu
TinkerlandsModsInstaller.exe --game "D:\Games\Tinkerlands" --remove mod-menu
TinkerlandsModsInstaller.exe --game "D:\Games\Tinkerlands" --recover
TinkerlandsModsInstaller.exe --catalog "C:\Packages\catalog.json" --list
```

## Публикация модов

Источники выбранных модов находятся в `mods/`, описание каталога —
`catalog/mods.json`. Поле `source` задаёт один GML-адаптер, `sources` задаёт
порядок объединения нескольких исходников, а `records` перечисляет дополнительные
записи мода в его папке `records/`.
В карточке мода отображаются `description`, необязательное подробное описание `details` и автор из `info.json`.
`tools/package.py` создаёт воспроизводимые `.mod`, ZIP,
`catalog.json`, EXE и `SHA256SUMS.txt` в `dist/`. В Releases публикуются EXE,
каталог, ZIP и суммы. Установщик берёт каталог из последнего обычного релиза
этого репозитория. Для выпуска мода используется опубликованный EXE текущей
версии и тег по шаблону `<mod-id>-vX.Y.Z`, например
`python tools/package.py --tag chest-network-v0.0.40`.
Шаблон Windows CI — `tools/build-workflow.yml`. Для включения его нужно поместить
в `.github/workflows/` с GitHub-авторизацией, имеющей право `workflow`;
в текущем репозитории он не активирован из-за отсутствия этого права.

Для новой DLL добавить в запись мода `native`:

```json
"native": [{"source": "build/example.dll", "name": "example.dll"}]
```

Сборщик проверит, что путь `mods/native/<mod-id>/example.dll` указан в адаптере.
Для модов с внутренними адресами игры указывать допустимые `game_sha256`.
Изменения основной игровой логики реализовывать в собственных AMD64 DLL;
`.mod` служит небольшим адаптером. Игровые бинарники/ассеты/сохранения,
личные журналы и исследовательские дампы в репозиторий не включаются.

Референс сценария работы — [установщик Risen Mods](https://github.com/LOTARLMEN/risen-mods/tree/main/installer).
Сетевой формат соответствует [GitHub Releases API](https://docs.github.com/en/rest/releases/releases)
и [Release Assets API](https://docs.github.com/en/rest/releases/assets).
